# AI Agent Skill Learning & Mindset Philosophies

This document explores the core philosophies of AI agent learning and teaching mindsets, specifically focusing on the "Skills" framework as defined by industry standards and popular implementations.

## 1. How AI Agents & Claude Skills Work (Greg Isenberg & Ras Mic)
**URL:** [https://www.youtube.com/watch?v=S_oN3vlzpMw](https://www.youtube.com/watch?v=S_oN3vlzpMw)

### Core Learning/Teaching Philosophy
*   **Progressive Disclosure:** The philosophy centers on token efficiency and context management. Instead of loading every instruction into the prompt (burning tokens and confusing the model), skills are "lazily loaded." The agent only sees the metadata (name/description) until it decides the skill is relevant.
*   **Experience-Driven Creation:** Skills should not be written in a vacuum. The best skills are created by walking through a workflow with an agent, achieving a successful run, and then asking the agent to "distill" that specific successful context into a permanent skill file.
*   **Recursive Refinement:** Failures are viewed as opportunities for the skill to "learn." When an agent fails, the correction is fed back into the skill's instructions or "gotchas" section to prevent future occurrences.

### Comparison to 'Stateful' Approach
The "Skills" framework is inherently stateful in its *persistence* but stateless in its *execution context*. It mimics a stateful "learning" process by updating a static file (the skill.md) based on session outcomes. Compared to a purely stateful approach where the agent's internal weights or a global "memory" might shift, this approach uses "state" via external file updates that the agent reads on demand.

## 2. The /teach Skill (Jake's Tech / Matt Pocock)
**URL:** [https://www.youtube.com/watch?v=iyqBpXOjefQ](https://www.youtube.com/watch?v=iyqBpXOjefQ)

### Core Learning/Teaching Philosophy
*   **Storage Strength vs. Fluency:** Based on the philosophy of Matt Pocock, this approach distinguishes between "fluency" (in-the-moment recall) and "storage strength" (long-term retention). The `/teach` skill deliberately introduces "desirable difficulty"—retrieval practice, spacing, and interleaving—to ensure the learner (or agent) actually masters the concept rather than just mirroring output.
*   **Canonical Grounding:** The agent is taught to distrust its own parametric memory (the training data) and instead build a "lessons" directory from high-trust, cited sources. It creates a structured learning path (MISSION.md) rather than answering one-off questions.
*   **Persistent Learning Workspaces:** Learning is treated as a project with a dedicated directory structure (lessons, reference, learning-records), making the learning process cumulative across sessions.

### Comparison to 'Stateful' Approach
This is a highly stateful implementation of a mindset. It uses the file system to maintain a "Learning Record" (ADR style). While standard LLM interactions are ephemeral, the `/teach` mindset treats the directory as the agent's long-term memory, adapting the curriculum based on the user's recorded progress.

## 3. 5 Best Practices for Building AI Agent Skills (IBM Technology)
**URL:** [https://www.youtube.com/watch?v=qYNs80FKIVc](https://www.youtube.com/watch?v=qYNs80FKIVc)

### Core Learning/Teaching Philosophy
*   **Trigger-Based Mindset:** The description is the "trigger." The agent must have a "pushy" description to ensure it recognizes when to apply its specialized knowledge.
*   **Human Domain Expertise:** The philosophy emphasizes that the LLM brings the "typing," but the human brings the "expertise." A skill should contain "gotchas"—environment-specific facts that defy reasonable assumptions—which the model could never know from training data alone.
*   **Deterministic Guardrails:** For fragile, multi-step jobs, the philosophy shifts from probabilistic instructions to deterministic code (scripts). If a step is too critical to be left to an LLM's "guess," it is offloaded to a script.

### Comparison to 'Stateful' Approach
This approach emphasizes "Context Engineering" over "Prompt Engineering." It aligns with a stateful approach by treating the "Skills" folder as a persistent "Digital Coworker Handbook." It moves the "state" of the agent's knowledge from the model's internal parameters to an external, version-controlled repository of scripts and markdown files.
