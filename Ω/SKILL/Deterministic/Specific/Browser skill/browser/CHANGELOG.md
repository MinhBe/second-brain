# Changelog

## 0.2.0 — 2026-09-15

- **`bw.mjs attach <url> -s <n>`**: joins the user's already-running Chrome (after the human ticks "Allow remote debugging" at `chrome://inspect/#remote-debugging`) and opens one new tab there, so their logins apply. Containment in code: a per-tab ownership mark (fixed `run-code` snippet) is checked before every page verb; the user's tabs are never selected, navigated, closed or read and are listed without title/URL; `state-save`/`state-load` are refused (7); `close` closes the skill's tabs and detaches, never Chrome. `playwright-cli attach --cdp` is no longer a human-only escape hatch.
- **R4 relaxed for attached sessions (TEMPORARY, user decision 2026-09-15)**: `attach`, and `goto`/`tabs --new` inside an attached session, accept provider hosts (claude.ai, chatgpt.com, meta.ai) so the user's already-signed-in Chrome profile can be used directly. Skill-launched sessions still refuse them. Hardening TODO: decide whether attached provider tabs should get the observer's audit trail (timeline, classifier, injection labels) or stay a plain browsing session; restore the refusal if not.
- **`bwp.mjs` (new, prototype)**: one tab in a CHOSEN profile of the user's running Chrome (`open <url> -s <n> --account <email>`), driven through Playwright `connectOverCDP` by CDP targetId; Chrome itself opens the tab (`--profile-directory=<dir>` handoff with a nonce URL) because CDP cannot create targets in a profile's context. A loopback daemon (`lib/bwp-daemon.mjs`) keeps one DevTools connection so Chrome ≥ 144's per-client "allow" prompt appears once per Chrome session. Verified live with profiles Default (365) and Profile 6 (665). Docs: `references/profile-attach.md`. No evals yet.
- **`bwp` daemon + permission note**: a loopback daemon holds one DevTools connection so Chrome's "allow remote debugging" dialog appears once per Chrome session, not per command. To stop Claude Code re-prompting before each `bwp` command, the user adds `"Bash(node C:/Users/Admin/.claude/skills/browser/scripts/bwp.mjs:*)"` to `permissions.allow` in `~/.claude/settings.local.json` (agents cannot grant themselves permissions). Persisting the Chrome toggle needs a user-run Local State edit (see `references/profile-attach.md`); driving a real logged-in profile exposes that account's cookies/session — an accepted Path B trade-off (2026-09-15).
- `doctor.mjs`: informational `chrome_remote_debugging` check (`chrome_devtools_port` field).
- `pwcli.mjs`: parses `### Session … attached to …`; maps `Could not connect … DevToolsActivePort` to exit 3 with the chrome://inspect instruction; prefers the `PlaywrightError:` line from a daemon crash.
- Evals: `bw-attach` (throwaway Chrome with `--remote-debugging-port`, `BROWSER_SKILL_CDP_ENDPOINT`), parser fixtures `attach`, `detach`, `detach-notattached`, `tab-new`, `runcode-owned-list`, `attach-noport`; `output-contract` covers the `attach` argument and precondition paths.

## 0.1.0 — 2026-09-11

and the hardened `ai-web-observer-SKILL.md` draft.
